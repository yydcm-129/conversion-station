# 转换空间站

当前版本：`v0.1.3`

`转换空间站.html` 是一个自包含、无需安装依赖的双向浏览器工具。它既能把 SillyTavern V1/V2/V3、TavernAI、RP-Hub、RisuAI、Agnai 等主流酒馆角色卡整理为 Moyun 小说设定，也能让用户自己的 AI 把 Moyun JSON/TXT 小说资料转换成可编辑、可导出的角色卡。v0.1.1 新增“聊天记录 → 小说”模式：导入 RP-Hub 聊天导出与对应角色卡，自动剥离 UI 数值块与思维链，把整理好的回合材料交给用户自己的 AI 写成墨韵格式小说。v0.1.2 新增“成品小说 → 可编辑小说”模式：导入 TXT/EPUB/Moyun JSON 成品小说，本地切分章节后可编辑、可让 AI 通读全书提取角色与设定，再导出 Moyun JSON / TXT / EPUB 三种格式。v0.1.3 按知轩藏书等精校 TXT 下载站的真实文件形态优化导入（作者识别、头部广告行清理、卷结构提取），并新增跨模式文件类型识别：把聊天记录、角色卡或小说错放进其他模式区块时，自动弹出确认弹窗询问是否跳转到对应模式重新导入。

## 主要能力

### 下载站 TXT 适配与错放文件识别（v0.1.3 新增）

- **作者识别**：三种常见形态——`作者：江南` 独立行、`《呢喃诗章》作者：咸鱼飞行家` 行内、`江南 著`；校对/整理人不误判为作者。识别结果填入“02 章节”页新增的作者输入框，可手工修改；导出 Moyun JSON / TXT / EPUB 均带作者字段（Moyun `novel.author` 为本站新增键，墨韵 v0.0.16 深合并保留，不影响旧版导入）。
- **下载站头部广告清理**：只清理**首个章节标题之前**的噪音行——`【…整理/收集/提供/校对…】` 声明、`本书来自：…`、裸网址行、`＊＊＊` / `=====` 分隔行等；首个标题之后的正文一字不动（呢喃诗章抽样清理前后章节切分完全一致）；≥40 字且含 ≥2 个句读分段的长行即使含敏感词也按正文保护不清理；导入状态栏报告清理行数。
- **卷结构提取**：`第 N 卷` 标题（中文数字/阿拉伯数字，前瞻匹配避免 `\b` 对中文失效）自动聚合为卷纲 `volumes`（id/标题/起止章/摘要），随 Moyun JSON 导出。
- **文件类型识别**：导入前按扩展名 + 结构特征判定文件是聊天记录（JSONL role 字段、单行 JSON 楼层、【玩家/AI/系统】标记）、小说（EPUB、章节标题行、Moyun JSON 结构）还是角色卡（PNG、spec/chara/first_mes 等）；TXT 只读头 16KB 评分，不动全文件。
- **错放跳转弹窗**：四个模式的导入入口（正向角色卡 / 聊天模式 / 成品小说模式）都接入检测——聊天 TXT 放进小说区、小说 JSON 放进聊天区、Moyun JSON 放进角色卡区等场景弹出确认弹窗，说明文件真实类型并询问“跳转并导入”还是“留在此页”；确认后自动切换到对应模式并把同一文件直接交给目标导入函数，无需重新选择。
- 检测失败或置信度低时按原流程处理，不误伤正常导入；弹窗可关闭（× / 留在此页 / Esc / 点击遮罩）。

### 成品小说导入（v0.1.2 新增）

- **三种输入**：TXT（UTF-8/GBK 编码自动探测）、EPUB 2/3（零依赖 ZIP 解包，兼容 STORE/Deflate 条目、`OEBPS/` 与根级两种 OPF 布局，按 spine 顺序提取正文）、Moyun JSON（单书/书库/`data` 包装均兼容）。
- **通用章节切分**：`第 N 章/节/回/卷/幕/话`、`楔子/序幕/序章/序/前言/引子/尾声/终章/后记/番外` 等核心词启发式；≤80 字、不含句读、不以逗顿号结尾，避免把“第一章正文甲。”这类正文行误判为标题；首个标题前的前言并入首章或独立成章。
- **书名识别**：`书名：` 前缀与 `《…》` 行（如“《呢喃诗章》作者：咸鱼飞行家”），识别不到用文件名。
- **四阶段流程**：01 导入 → 02 章节预览编辑（搜索/过滤/编辑/删除/重切分：按标题模式或约 3,000/6,000 字强行分段；>400 章渲染封顶）→ 03 识别 → 04 导出。
- **本地整理（无 AI）**：零 API 调用，只整理书名与章节结构，正文原样保留。
- **AI 准确识别优化模式（长模式）**：三步流水线多轮调用 API 通读全书——规划轮（章节标题+首尾片段 → 简介与世界观初稿）→ 逐批精读轮（8/16/32 章每批，AI 增量提取角色、世界观、大纲）→ 合并轮（去重合并）；超预算章节可“保留头尾并标注省略”或完整保留；批次进度面板实时显示，顶部“停止 AI”可中止且保留已完成批次。
- **精读安全边界**：只提取正文中已经出现的角色、关系、地点、势力与世界观事实，严禁虚构新人物、新设定、新剧情或结局；正文永不改写；关系态度 ≤30 字、变化原因 ≤120 字、台词整句。
- **三种导出**：Moyun JSON（`_exportVersion: 9`，可直接在墨韵导入）/ TXT / EPUB 3（无脚本、无外链、全转义，7-Zip 独立解包校验通过）+ 复制 JSON。
- 导入解析全程本地；未点 AI 精读时零网络请求。

### 聊天记录转小说（v0.1.1 新增）

- **开场预设楼层**：导入角色卡后 first_mes 与全部 alternate_greetings 自动作为“预设”楼层展示在列表头部（紫色标记），可编辑/删除/纳入；重选分支自动保留。
- **白天/黑夜双主题**：顶栏 ◐ 按钮切换，选择自动记忆；亮色主题全站适配（含弹窗、状态、楼层、按钮）。
- **正向/反向分批生成**：AI 整理与反向生成同样支持 agent 式三阶段分批（规划→逐组→合并），材料超预算自动触发，也可强制“始终分批”或关闭；每模式旁有独立选择器。避免超大角色卡/超长小说一次性发送导致的上下文溢出错误。
- **角色卡原卡必选**：先上传角色卡（.json/.png）才能导入聊天记录；未导卡时导入被拦截。角色卡提供“数值基准”，防止 AI 虚构设定。
- **通用 UI 自动发现引擎**：导入角色卡时自动扫描世界书、UI 模板与正则脚本，发现该卡的 UI 模式（自定义标签对、JSON 标签块、分隔线面板、【状态栏】变体等，上限 40 条）；导入聊天记录后按发现的模式提取未知格式数值块，无需针对每张卡硬编码；内置五种常见格式兜底叠加生效。
- **user 个人设定（选填）+ 人称自适应**：支持文件导入（.json/.txt/.md，兼容酒馆 persona 格式）或直接粘贴；提供 persona 时 AI 以该角色名行文（不再用第二人称“你”），未提供时保持第二人称。
- **agent 式分批生成**：长文本多轮调用——规划轮（时间线→章节划分）→ 逐章轮（本章回合 + 前章衔接摘要）→ 角色整理轮；支持自动/始终/从不三档；每章完成即写入结果编辑器可中途保存；分批计划面板实时显示进度。
- **系统楼层（酒馆式分类）**：楼层分 系统/用户/AI/旁白 四类；role=system 或名字含“系统/世界书”且原始角色非 user/assistant 时识别；可筛选、编辑、新建（＋系统/＋用户楼层按钮）；材料以【系统】前缀标注，仅作背景理解不入正文。
- **AI 依赖提醒**：界面明确提示“转小说正文必须依靠 AI（本地无法处理大量文本）”；本地按钮“导出纯文字记录”只提取文字不做修改。
- 导入 RP-Hub 分支聊天导出（`type: rp-hub-branch-chat` JSONL）或每行一楼消息的纯消息 JSONL；多条分支可任选一条加载。
- 自动识别并剥离常见 UI 数值块：【状态栏】文本行、`<status>` JSON、`<ui_template_updates>` 变量更新（含无 `updates` 包装的裸变量对象）、`<template_state>` 模板状态、`────` 分隔的多段文本面板。
- 自动清理非叙事噪音：`<cot>` / `<reasoning>` 思维链、`<actions>` 选项、`<state>` 内联变量、`<known_info>`、`<rphub-magia-keepalive>`、`image###…###`、iframe HTML 和 `/send` 等命令前缀。
- 所有提取到的数值块按楼层顺序聚合成“UI 数值时间线”，作为背景参考发送给 AI 判断剧情走向与章节划分；提示词明确禁止把数值面板原文写进正文。
- 楼层列表支持搜索、按纳入/未纳入/已编辑/新增/角色（含系统楼层）过滤；全选/清空；超过 400 楼时仅渲染前 400 条并提示继续搜索。
- 点击任意楼层可编辑角色、名字与内容（保存后重新提取数值块与清理噪音）；可新建空白楼层（系统/用户/旁白）写入自己的旁白或格式要求；可删除楼层并自动重排编号。
- 点击页面版本号徽章可打开“对话总览”弹窗，查看当前对话的全部楼层、纳入/编辑/新增统计，并可从总览直接编辑、删除或新建系统楼层。
- 回合合并：按字数（不合并/2000/4000/6000/8000）把相邻楼层合并为回合，用户楼层换回合优先在“【玩家】发言”处断开；发送预算不足时可选择“截断保留首尾”或“不截断”。
- 可在“自定义格式要求”输入框写入额外要求，随材料一起发送。
- 预设导入导出：把回合字数、截断模式与自定义要求导出为 JSON 预设分享给他人，导入时校验 `_type` 标记。
- 生成时与正向/反向共用 API 设置与全局“停止 AI”按钮；流式/JSON Object 兼容重试逻辑与反向一致。
- 结果编辑器可直接改写 Moyun JSON 再导出；支持下载 Moyun JSON、复制 JSON、导出 TXT 小说。
- “导出本地回合纪事”可在不使用 AI 的情况下导出清理后的回合 TXT 底稿。
- 输出结构 `_type: moyun_character_card_conversion`、`_exportVersion: 8`，与正向模式一致，可直接在墨韵“导入 JSON”中使用。

### 角色卡转小说设定

- 导入单个 `.json` 或带角色元数据的 `.png` 角色卡。
- 解析 PNG 中 `tEXt`、`zTXt`、压缩/未压缩 `iTXt` 文本块里的 `chara`、`ccv3` 或其他 JSON/Base64 角色数据。
- 兼容标准 Base64、Base64URL、缺失 padding、多层 `data/card/character` 包装及字符串化 JSON 包装。
- 自动显示 RP-Hub、RisuAI、Agnai、SillyTavern V2/V3、Tavern 兼容卡及 PNG 元数据来源。
- 兼容常见名字、描述、人格、开场、备选开场、场景、示例对话和世界书字段别名。
- 兼容世界书数组、对象映射、单条对象及 `entries/items/data/lore` 等容器变体。
- 无世界书的简单卡会从人物描述与人格生成一个可复核的人物设定条目。
- 自动识别 `user`、`User`、`{{user}}`、`{user}`、`<user>`、`[user]`、`${user}` 等玩家占位符：人物名称与关系目标统一为“主角”，叙述内容转换为第二人称“你/你的”。
- “老年 {{user}}”“未来的你”等玩家阶段形态会合并到主角，不再生成独立伪角色。
- 最终导出会再次递归清理全部字符串字段；`username`、`end-user` 等非占位符单词保持原样。
- 自动把世界书条目初分为世界观、人物、剧情素材、资料库、规则/机制、UI/格式。
- “02 筛选”中的每个条目均可点击或用键盘打开完整预览，并可在预览中前后切换、保留或取消保留。
- “预览已选”可只浏览当前勾选的条目，数量会与复选框实时同步。
- 识别“代号103设定”“某某角色设定”等“人物名+设定”条目，不再误归为剧情素材。
- 可从复合 personality 中拆分多个人物，并从交友圈、人物关系等条目中保守提取嵌套角色。
- 识别主线大纲、章节流程、章节运行、战役大纲等高置信度剧情条目，并与普通“剧情连接”“剧情模板”区分。
- 大型数据库卡优先推荐明确剧情、原创同伴和主线角色；一次最多渲染 500 条，可按分类或关键词搜索全部世界书。
- 识别 `BG4_NPC|编号|人物 - 分片`、`COMPANION` 等结构化人物分片，并按真实姓名合并。
- 默认排除 UI、HTML、CSS、正则、状态协议、数值面板、结局池和事件触发器。
- 从 `uiTemplates`、`rp_hub_ui_templates`、UI 世界书条目和 UI 相关正则中生成独立 UI 包 JSON。
- UI 包拥有独立项目列表、源代码视图和沙箱预览；脚本、正则和事件不会执行，外部网络资源被 CSP 阻止。
- 区分叙事开场与玩家身份/资料填写页；填写页不会进入第一章。
- 从 HTML 开场白中只提取可读剧情文字，并保留 `“”`、`「」`、`『』`、`〖〗` 等原始符号。
- 本地规则转换无需联网。
- 右上角设置在导入前即可使用，可测试连接、获取模型并选择模型。
- 可选连接用户自己的 OpenAI Chat Completions 兼容 API，让 AI 整理人物、世界观，并在用户启用时把角色卡已有剧情合并为故事大纲。
- AI 大纲只允许整理卡内现有总纲、章节、冲突、转折、分支和结局条件，不续写正文、场景、对白或细纲。
- 检测 `bg4_remote` 及同类远程/云端加载声明；本地内容不完整时阻止转换，并展示角色卡声明的 HTTP/HTTPS 来源地址。
- 远程来源只显示，不会自动访问或下载服务器内容。
- 兼容 OpenAI SSE、NDJSON、字符串或数组形式的 `delta.content`，流式或 JSON Object 模式不兼容时会自动回退。
- API 输出 token 上限可选 4096、8192、16384 或 32768；正向与反向默认 8192，大纲分析最多 4096，不支持该参数的接口会在最终兼容请求中移除它。
- AI 返回完整 JSON 后附带说明文字或第二个 JSON 时，只读取第一个完整对象；仅末尾引号或容器闭合符缺失时进行受限修复，无法可靠判断的截断会明确报错。
- 三条 AI 流程共用顶部“停止 AI”按钮，可立即中止正向整理、独立大纲分析或反向角色卡生成；停止后不会继续兼容重试，也不会覆盖已有结果。
- 输出 Moyun 接受的 `novel + chapters + characters` JSON，并可把来源剧情写入 `novel.outline`。
- 导出 JSON 携带 `novel.volumes`（墨韵 v0.0.10+ 卷纲结构：卷名、章节范围、框架摘要）。
- 支持 Moyun JSON、通用设定 JSON、TXT、Markdown 和自定义文本扩展名导出。
- 只把原角色卡开场白放入第一章，不生成后续正文、细纲或额外章节。
- 响应式界面，支持桌面与移动端；条目勾选框等触控目标已按手机尺寸放大（26px，≤520px 视口 28px）。

### 小说设定转角色卡

- 导入 Moyun 单书 JSON、书库 JSON、`data` 字符串包装备份、转换空间站设定 JSON 或 Moyun TXT。
- 读取墨韵 v0.0.10+ 的卷纲与章节剧情时间元数据；旧版无这些字段的 Moyun JSON/TXT 仍可正常导入。
- 使用“01 导入 → 02 分类 → 03 生成 → 04 导出”四阶段流程，同一时间只显示当前阶段。
- 小说材料拆分为基础设定、世界观、角色、故事大纲、规划数据和章节正文，卷纲逐卷作为大纲条目推荐发送；可按类别与关键词筛选、逐项勾选并预览实际发送给 AI 的内容。
- 台词示例按墨韵 v0.0.11 整句规范解析：按换行与句末标点拆分，逗号、顿号不拆句；关系态度与变化原因按墨韵字数上限（30/120 字）截断。
- 推荐选择默认保留设定、角色和既有大纲，默认排除章节正文；用户仍可手工调整每个条目。
- 只把小说正文当作已有事实材料，AI 提示词禁止续写正文、补写结局或虚构关键设定。
- 人物、世界观、关系、地点、冲突、互动入口和已有大纲事实会先整理为统一的可编辑角色卡结构。
- `user`、`{{user}}` 等玩家占位符不会被选为主角色；提示词中统一说明它们表示玩家而非人名。
- 输出可选 RP-Hub、SillyTavern V1/V2/V3、TavernAI、RisuAI 或 Agnai JSON。
- 上传 PNG/JPEG/WebP/GIF 等图片后会先转换成 PNG，再写入 `chara`；SillyTavern V3 同时写入 `ccv3`。
- 正向模式提取到的 UI 包会存入浏览器 IndexedDB；反向模式可逐包勾选模板、UI 世界书、正则及顶部/底部位置。
- UI 包预览继续使用无脚本、禁止外部连接的沙箱，不执行角色卡脚本或正则。
- “过审助手式”完善是默认关闭的可选检查，只提示开场可玩性、关键词、常驻条目负担和需要人工复核的发布风险，不阻止导出、不自动删除题材内容，也不把 15,000 字作为唯一标准。

## 使用方法

### 成品小说导入

1. 点击顶部“成品小说 → 可编辑小说”进入第四模式。
2. 在“01 导入”选择 TXT / EPUB / Moyun JSON；解析完成后显示来源类型、章数与总字数。
3. 在“02 章节”检查切分结果，可改书名、搜索过滤、编辑/删除章节或重新切分（按标题模式 / 约 3,000 / 6,000 字分段）。
4. 在“03 识别”选择本地整理（无 AI）或 AI 准确识别优化模式（多轮通读全书提取角色与设定，详见 `NOVEL_IMPORT_GUIDE_v0.1.3.md`）。
5. 在“04 导出”复核识别字段，下载 Moyun JSON、TXT 或 EPUB，或复制 JSON。

### 角色卡转小说设定

1. 双击打开 `转换空间站.html`。现代浏览器可直接使用；若浏览器限制本地文件功能，也可通过任意静态网站托管。
2. 如需 AI，可先点击右上角设置图标，填写地址、密钥并获取模型；也可以完全跳过。
3. 导入一张受支持的主流酒馆 `.png` 或 `.json` 角色卡。
4. 点击顶部四个阶段切换页面，检查自动分类结果；点击条目可看完整内容，再勾选需要保留的小说设定。
5. 如角色卡含 UI，可在“角色卡 UI 包”区域预览、复制或下载独立 UI 包 JSON。
6. 如检测到剧情材料，可在 AI 区选择是否合并为故事大纲；本地转换只按原文提取。
7. 选择本地转换，或使用已配置的 AI 整理。
8. 检查书名、简介、世界观、大纲、角色数组和第一章开场白。
9. 选择 Moyun JSON、通用设定 JSON、TXT、Markdown 或自定义文本扩展名并下载。
10. Moyun JSON 可在 Moyun 的“导入/导出 → 导入 JSON”中直接导入。

如果页面提示“远程依赖角色卡”，说明 PNG 本地没有完整世界书。转换按钮会被禁用，请从页面列出的来源地址取得完整本地版本后重新导入。

### 小说设定转角色卡

1. 点击顶部“小说设定 → 角色卡”。
2. 在“01 导入”选择 Moyun `.json` 或 `.txt`，确认识别到的书名、角色和章节数量。
3. 进入“02 分类”，按基础设定、世界观、角色、大纲、规划或正文筛选；推荐状态默认不发送正文，可逐项调整并查看 AI 材料预览。
4. 进入“03 生成”，在 API 设置中填写用户自己的兼容接口、密钥、模型和输出 token 上限。
5. 选择目标格式、可选主角色，以及是否允许拆分已有大纲事实。
6. 如需参考发布检查，再手动启用“过审助手式”可选完善；如需复用 UI，勾选已缓存 UI 包并配置资产和位置。
7. 点击“使用 AI 生成角色卡”；运行中如需取消，点击页面顶部“停止 AI”。
8. 生成成功后自动进入“04 导出”，复核并编辑统一角色卡 JSON，再下载目标格式；如需 PNG 卡，上传图片后点击“生成 PNG 角色卡”。

### 聊天记录转小说

1. 点击顶部“聊天记录 → 小说”进入第三模式。
2. 在“01 导入”选择 RP-Hub 聊天导出 `.jsonl`/`.txt`；如需数值基准，可再导入对应角色卡 `.json`/`.png`（可选）。
3. 在“02 楼层”确认已加载的分支（多分支卡可任选），搜索/过滤/勾选要保留的楼层；点击楼层可编辑内容，或新建空白楼层写入自己的格式要求。
4. 在“03 材料”选择回合合并字数与截断模式，检查回合预览、UI 数值时间线与角色卡基准；可在自定义要求框写入额外格式要求。
5. 点击“使用 AI 写成小说”，或先用“导出本地回合纪事”导出未改写的 TXT 底稿。
6. 生成完成后在结果编辑器中复核/修改 JSON，再下载 Moyun JSON、复制或导出 TXT。
7. 预设按钮可导出当前配置为 JSON 分享给他人，或导入他人预设。

### AI 接口

详细规则见 `CHAT_NOVEL_GUIDE_v0.1.1.md`。默认接口示例为：

```text
https://cdn.sta1n.cn/v1
```

可以替换为其他兼容 Chat Completions 的服务。填写基础地址即可，工具会调用 `/models` 和 `/chat/completions`；即使粘贴了完整的 `/chat/completions` 地址也会自动归一化。工具默认优先发送 `response_format: {"type":"json_object"}`，失败时会用普通非流式请求自动重试。

输出 token 上限默认是 8192，可在设置中调整；独立大纲分析自动限制为 4096。若接口不接受 `max_tokens`，最终兼容请求会移除该字段。停止按钮使用浏览器 `AbortController` 中止当前请求，中止后不会触发下一次兼容重试。

- API Key 默认仅保存在当前页面内存中。
- 即使选择保存接口设置，也不会保存 API Key。
- 只有点击正向“使用 AI 整理”、正向“AI 分析并填写大纲”或反向“使用 AI 生成角色卡”时，对应预览材料才会发送给用户配置的接口。
- 纯浏览器页面需要接口允许 CORS；不允许时需使用用户自己的安全中转服务。

## 输出约束

- 没有明确剧情或用户关闭大纲整理时，`novel.outline` 为空。
- 启用剧情整理时，`novel.outline` 只包含角色卡原有剧情的提取或 AI 归并结果。
- `chapterOutlines`、`chapterIndexDrafts`、`foreshadowMatrix` 固定为空数组。
- 不生成总结、正文续写或额外章节。
- 不生成逐章细纲；`chapterOutlines` 和 `chapterIndexDrafts` 仍保持为空数组。
- 有有效开场白时只生成一个名为“开场”的章节。
- 不导出角色卡原图、UI 模板、正则脚本或 RP-Hub 运行配置。
- UI 包与 Moyun 小说 JSON 始终分开导出，UI 内容不会作为世界观、角色或正文写入小说文件。
- 不允许玩家占位符作为真实角色名或残留在书名、开场、人物、世界观和人物关系等输出字段中。

## 本地验证

已含成品小说导入测试时运行：

```bash
npm test
```

若 PowerShell 阻止 `npm.ps1`，可改用 `npm.cmd test`。聊天模式浏览器探针需先启动夹具服务：

```bash
node tests/browser-fixture-server.mjs
node tests/chat-mode-probe.mjs
```

第四模式浏览器端到端探针：

```bash
node tests/novel-mode-probe.mjs
```

正向/反向分批生成探针（验证三阶段流水线与合并结果）：

```bash
node tests/browser-fixture-server.mjs
node tests/batch-mode-probe.mjs
```

也可指定其他转换结果：

```bash
node tests/verify-output.mjs "路径/转换结果.json"
```

## 数据与版本原则

- 示例角色卡、小说 JSON 和两个参考仓库始终保持只读。
- 每个正式版本使用独立 Git 提交、标签和测试报告保留回滚点。
- 项目目录在发布后只显示最新正式版本号。
- `v0.0.1` 是首个版本；版本号不限定固定进制。
